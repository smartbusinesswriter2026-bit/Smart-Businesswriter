# business_pipeline (Stage 5 first increment)
Tests: `python3 -m unittest discover -s tests -v` (run from this folder; Python 3.10+, stdlib only)
Run the workbench: `PYTHONPATH=src python3 -m bp.server 8000` then open http://127.0.0.1:8000
API: POST /api/sessions, POST /api/sessions/{id}/confirm|reject, GET /api/sessions/{id}, GET /api/presets
API also: GET /api/methods (discovery, never executes). Methods: npv, breakeven, descriptive_stats, pearson (falls back to spearman), spearman, ols (falls back to ols_robust), ols_robust, welch_t (falls back to mann_whitney), mann_whitney, anova (falls back to kruskal_wallis), kruskal_wallis, chi_square, trend_forecast (linear trend with prediction intervals and an out-of-sample holdout), ratio_analysis (15 declared financial-statement ratios from supplied figures, T1), paired_t (within-pair differences, T1), one_sample_t (one mean against a declared reference, T1), wacc (weighted average cost of capital from declared inputs, T1), dcf_valuation (discounted cash flow with optional Gordon growth, T2), multiple_comparison (Holm/Bonferroni correction over one declared family of p-values, T1), power_analysis (power and minimum detectable effect for a planned mean comparison, normal approximation declared, T1), missing_data_bounds (extreme-case bounds for the complete-data mean with a declared, unverified missing-data mechanism, T1), weighted_summary (weighted mean/sd, effective sample size and design effect under declared reliability or frequency weights, summaries only, T1), management_accounts (declarative ledger engagement, T2, with the account-mapping checkpoint and accountant-facing statement exports). See docs/ for decisions, limitations, STAGE0_REPORT.md and STAGE5_REPORT.md.

Sandbox: the server runs computations in a guarded subprocess by default (`python -m bp.server 8000`). Use `--no-sandbox` only for development.
Re-performance: `python -m bp.reperform bundle.json` (set PYTHONPATH=src) re-runs a delivered bundle and compares outputs.

Registry (Stage 6): `src/bp/data/registry_v0_2.json` is generated from the catalogue: `PYTHONPATH=src python -m bp.catalogue_import docs/sources/Business_Frameworks_and_Quantitative_Methods_Catalogue_v0_2.md src/bp/data/registry_v0_2.json`. API: GET /api/frameworks?q=&type=, GET /api/frameworks/{id}; POST /api/sessions/{id}/confirm accepts {"frameworks": [ids]}. A request with no `method` returns a framework-only (T4) answer.

Templates: methods `template_swot` and `template_five_forces` take your own evidence (see GET /api/templates for the input format and an example). They organize and audit evidence; they compute and invent nothing.

Business case: method `case_decision` compares 2-5 of your own alternatives by NPV, finds where the ranking changes across your rate range, and states a preference only under your decision rule. See GET /api/templates/case_decision for the input format and an example.

Spike (Stage 8): `python spike/run_custom_arm.py` runs the ledger trap cases against the custom kernel (src/bp/ledger.py). Schedule engines (src/bp/schedules.py): straight-line depreciation (with declared prospective policy changes), loan amortization and accruals that generate journal lines posting into the kernel. The kernel also computes a cash flow statement by two routes (`cash_flow`), period-end closing with the retained-earnings rollforward (`closing_entries`, `retained_earnings_rollforward`) and period chaining (`closing_balances`, `opening_lines`). The declarative layer (src/bp/accounts.py) is wired into the pipeline as the `management_accounts` method, with the manual's second mandatory checkpoint (confirm the account mapping before anything is posted), an optional external-statement reconciliation (src/bp/reconcile.py) and accountant-facing plain-text statement exports (src/bp/report.py). See docs/STAGE8_SPIKE_REPORT.md. The research workflow (formerly Build Charter Stage 7) is defined by its living manual: docs/RESEARCH_EVIDENCE_WORKFLOW.md.

Model assistance (optional, off by default; providers: `deepseek`, `openai`, `anthropic`): see docs/MODEL_PROVIDER_REPORT.md for setup (environment variables) and the rules it runs under. The model proposes; code validates; you confirm; it writes no numbers.

Ingestion: `POST /api/ingest` {filename, content_base64} reads a CSV/TSV or XLSX file into a typed table with a provenance pointer (file, SHA-256, row/column); the workbench has a Data ingestion card and `python -m bp.ingest <file>` prints the same summary. PDF, scans and SPSS are refused: no OCR or PDF text extraction is implemented.

Product gaps and the recommended build order: docs/PRODUCT_GAP_MAP.md. Documentation spine: docs/HANDOFF.md (handoff brief for the next coding agent), docs/HOME.md (map of the repository), docs/CONTRIBUTORS.md (rules for any model or person changing it), docs/WORKLOG.md (append-only log of what was done), docs/DECISIONS.md, docs/KNOWN_LIMITATIONS.md and docs/CHANGELOG.md.

Research & Evidence Workflow (REW, formerly Stage 7) literature source (first slice): `src/bp/literature.py` resolves and verifies references by DOI (Crossref primary, OpenAlex fallback), audits each resolved retrieval with a SHA-256 of the response bytes and a UTC retrieval time (B-054), appends it to a durable local retrieval log (`BP_RETRIEVAL_LOG`, default `retrieval_log.jsonl`; empty disables) with fail-closed writes and `reverify` (B-058), and formats citations in the owner-ratified **APA 7** and **Harvard** styles (B-059). API: `GET /api/literature/sources`, `POST /api/literature/verify` {title, doi?, source?, cite?: "apa"|"harvard"}, `GET /api/literature/log?limit=`, `GET /api/literature/drift?limit=` (manual drift sweep), and `python -m bp.literature drift [log] [limit]`; the default source is `auto` (Crossref, then OpenAlex, every attempt logged). The workbench has a References panel with a style selector, citation, retrieval-log and drift views. The REW stages are proposed, not built: docs/RESEARCH_EVIDENCE_WORKFLOW.md.

Evaluation (optional, PROVISIONAL): `PYTHONPATH=src python -m bp.evaluate tests/fixtures/eval_cases.json` scores model proposals against held-out gold data (needs a configured provider). See docs/MODEL_PROVIDER_REPORT.md.
