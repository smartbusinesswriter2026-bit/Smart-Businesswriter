# Product backend plan (after the freeze)

**Status: PROVISIONAL plan, owner instruction "finish the backend product before finally doing the UI".** The core is frozen (B-079); the product backend is the design owner's lane and is additive only (B-080). This file fixes the order, the owner of each slice, the gates, and the boundary rules that keep the frozen contract intact while both owners work in the same repo.

Read with [`BACKEND_CONTRACT.md`](BACKEND_CONTRACT.md) (frozen core) and [`DECISIONS.md`](DECISIONS.md) B-079/B-080/B-081.

## Phase 0 — owner decisions that shape the backend

These do not block slice 1 (which is built to the conservative default in the third column), but they must be answered before any hosted/multi-user work or any promise about data retention.

| # | Question | Recommended default (slice-1-safe) | What changes if the owner chooses differently |
|---|---|---|---|
| D1 | **Deployment model**: local single-user, or hosted multi-user? | **Local single-user v1**: one person, one machine, files on disk, no accounts. | Hosted brings accounts/auth, tenancy isolation, backups, rate limits and a security review; the case store's storage layer changes but the frozen computation does not. |
| D2 | **Case retention/privacy**: how long are cases kept, who may delete them, is any case content sent anywhere? | **Keep until the owner deletes; no outbound transfer; model assistance stays opt-in and off by default (already true).** | A retention policy adds expiry/export-before-delete rules; privacy law review is needed before hosting. |
| D3 | **AI-use disclosure audience**: for an assessor/reviewer, an institution, or an internal file? | **A reviewer/assessor-facing disclosure** generated from recorded metadata (method id/version, spec hash, tier, run id, environment hash, declared inputs provenance, model-assistance calls if any, verification checks, timestamps). | Different audiences change what is shown (e.g. institution paperwork) but not what is recorded, because the record already exists. |
| D4 | **Reviewer sign-off semantics**: what does a signature assert? | **"I reviewed the named bundle and its disclosed limitations"; it does not assert the inputs are true or the analysis is correct.** | A stronger claim needs a named reviewer (B-005) and a process; the record schema stays the same. |

## Phase 1 — slice 1, delegated to the design owner (MiniMax)

Delivered as one product increment against the frozen core, with no unfreeze.

**1a. Case workspace store (local, durable).**
- New package `src/bp/product/` (new files only; it imports the frozen core, never modifies it).
- Stores a **case bundle** as one JSON document per case under a data directory (`BP_CASES_DIR`, default `cases/`): the session JSON (`session.to_dict()`), the delivery `report` + `appendix`, the `reperform` bundle, and case metadata (`id`, `title`, `created_at`, `method`, `tier`, `spec_hash`, `outputs_hash`). The bundle is an **opaque document**: the product layer does not reinterpret, recompute or "fix" any number in it.
- Atomic writes (write-temp-then-rename), `id` generated by the product layer (hex), path-traversal refused, a corrupt bundle refuses to load with a clear message, delete removes the file.
- Additive routes: `GET /api/cases`, `POST /api/cases`, `GET /api/cases/{id}`, `DELETE /api/cases/{id}`. No route computes; loading a case shows the stored report verbatim.

**1b. Disclosure export.**
- A function/route that renders the recorded metadata of one bundle into a plain-text (later styled) **AI-use disclosure**: what was computed, by which method version, under which spec hash and environment, which checks passed, which inputs were owner-supplied vs retrieved, whether model assistance was used at all, and the declared limitations. Every field comes from the stored bundle; the disclosure **adds no claim** and says explicitly that it records process, not correctness.

**1c. Report export in Office formats.**
- DOCX/XLSX export that renders the stored report text verbatim and the artifacts table from the appendix. The exported document must contain the same numbers, caveats and honesty notices as the delivered report — no re-rounding, no summarising, no restyling of claim wording. If the frozen `report.py` plain-text export is used as the source, its output is copied, not paraphrased.
- Dependency rule: new third-party libraries are allowed in the **product layer only** (they are not imported by `src/bp/**` core modules), and the runtime stays standard-library for the core. If a library is needed, the design owner records it in the product documentation.

**Boundary rules for this slice (binding):**
- May create: `src/bp/product/**` (new files), `tests/test_product_*.py` (new flat test files), `web/**` presentation, product docs.
- May edit for its own increment, and only these: the **count/version digits** in `docs/HOME.md`, `docs/HANDOFF.md`, `docs/CONTRIBUTORS.md`; one `CHANGELOG.md` entry; one `WORKLOG.md` entry tagged `[product]`; its own rows in `BACKEND_CONTRACT.md` §6.
- May **not** edit: any frozen core module, any existing test or fixture (`tests/fixtures/frozen_contract.json` included), `docs/DECISIONS.md`, `docs/BACKEND_CONTRACT.md` §1-§5, `docs/KNOWN_LIMITATIONS.md`, `docs/PRODUCT_GAP_MAP.md`, `docs/RESEARCH_EVIDENCE_WORKFLOW.md`, or any caveat/honesty/claim wording.
- The suite must be green including `tests/test_frozen_contract.py` and `tests/test_docs_sync.py`. The computation owner reviews the numeric doc edits at merge.

## Phase 2 — slice 2, delegated to the design owner

- **Reviewer sign-off record** on a case: reviewer name/role (owner-supplied), scope, decision, timestamp, and the hash of the exact bundle reviewed. The record is additive metadata; it changes no number.
- **Model pinning / drift gate surface**: display and record which model id/version was used for optional assistance, with the existing `assist`/`llm` contract; no new model capability.
- **Ops and observability**: request log that excludes case content and personal data, model-call counters/budgets, health endpoint, export/backup-restore of the case directory.
- **Offline packaging**: a single local install/run path for the frozen core + product layer (stdlib core preserved), with a version pin and a windowless start.

## Phase 3 — computation owner, needs an unfreeze (owner approval, B-079)

Ordered by product value:

1. **Multi-period comparatives / report versioning with diffs** — touches spec/artifacts/delivery; unfreeze request with a mini-spec (same method, several periods, deterministic diff of outputs).
2. **PDF/scan/OCR + SPSS ingestion** — extraction pipeline plus a human-confirmation step for unverified text; unfreeze because the ingest contract changes.
3. **Core-lane exports** if the Office export must live in `report.py` rather than the product layer (prefer product layer).

Each starts as a request in this file; nothing here is approved yet.
